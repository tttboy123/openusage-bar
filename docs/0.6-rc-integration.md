# OpenUsage Bar 0.6 RC 集成候选

本文记录 0.6 RC 的本地集成事实。它不是发布公告，也不代表公开 Canary
已经开始。

## 集成范围

候选分支 `integration/0.6-rc` 以 release hardening 为基础，统一装配了此前
独立审查的功能切片：

- Codex 本地 Token 历史与订阅额度对账；
- MiniMax 中国站、国际站的数据源隔离；
- Cursor 剩余额度语义；
- Kiro / CodeWhisperer 订阅额度语义；
- OpenAI Organization cache、input、output 与 total 用量；
- Claude Code、OpenCode 等本地客户端覆盖检查；
- GLM、Kimi、Qwen 等 Provider 的权威来源审计；
- Moonshot / Kimi 官方余额接入；
- Provider Adapter Kit；
- Supported Billing/Cost 与 `api_spend` source fact 的目录一致性约束；
- Local API v1 N-1 兼容策略；
- PR CI 与 Pre-release 的依赖审计及隔离安装/升级/回滚门禁对齐；
- 无遥测 Canary 入口，包含脱敏 Balance 与能力证据聚合；
- 常驻进程性能预算。

对应的独立审查记录为 Draft PR #35 至 #47；release hardening 基线为
PR #15。集成 PR 是唯一的 0.6 RC 共存候选，独立 PR 继续保留为设计与
审查证据，不应被逐个当作完整产品候选发布。

## 集成时发现并修复的问题

Moonshot 余额接入为 `/v1/snapshot` 新增 `balances`。Local API v1 兼容
策略规定 additive 字段不得在同一 major 版本中变为必填，因此当前 Schema
保留 `balances` 的类型约束，但不要求旧 snapshot 必须包含该字段。

验证同时覆盖：

- 当前校验器读取冻结的 0.4.2 N-1 snapshot；
- 当前校验器读取带未知 additive 字段和 `balances` 的 snapshot；
- 当前 Server 输出仍包含 `balances`；
- 未知字段不能绕过凭证与隐私字段检查。

  使用同一版本身份；

- Swift：255 项、21 个 Suite 通过；

- release secret tree scan：0 项；

- `dist/OpenUsage Bar.app` 构建成功；
- Provider Adapter Kit 在全新 detached worktree 中按公开文档直接通过
  14-case Conformance，随后 clean-checkout build 通过；

版本身份审计首先从提交 `e3dcf45` 的 CI 制品发现：集成分支虽然名为
`0.6 RC`，产物仍自报 `0.4.4 (8)`，因此不能作为可区分的外部 Canary
候选。当前修复使用 RED → GREEN 的 Bundle 契约升级到 `0.6.0 (9)`；本地
重建后 ZIP、DMG checksum、release artifact audit、SPDX SBOM、隐私扫描及
隔离 clean install / upgrade / rollback / uninstall 全部通过。未提交工作树
生成的本地包只用于验证，不发布；可分发候选必须由提交后的远端 CI 重新生成。
