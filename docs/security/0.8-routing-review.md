# OpenUsage Bar 0.8 routing security review packet

Status: **local pre-review evidence; independent approval pending**

Candidate exercised locally: `0.8.3 (20)`

Public release baseline: `0.6.0`

This document gives an independent reviewer a bounded target. It does not
declare the 0.8 candidate secure, start the external Canary, or authorize a
public release.

## Security objective

Smart Routing may select and, only after explicit opt-in, execute an LLM
request. It must not turn the usage product into a remotely reachable gateway,
expose Provider credentials to SwiftUI or JSON, persist model content, weaken
the read-only Local API, or make routing failure stop fact collection.

## Assets and trust boundaries

| Asset or boundary | Required property | Implemented control |
| --- | --- | --- |
| Provider credential | Never returned to UI, API, CLI, logs or evidence | Stored in macOS Keychain; Provider reuse copies it through a foreground Python Controller action into an isolated `routing.<connectionRef>` account |
| Proxy Bearer capability | Possession is required; plaintext is not persisted | Generated with the platform CSPRNG, returned once, length checked, compared through an HMAC-safe digest comparison; only SHA-256 verifier is stored in a mode-`0600` document |
| Prompt, response, tools and request headers | Transient forwarding only | In-memory forwarding; excluded from SQLite, routing attempts, diagnostics and application logs |
| Loopback HTTP boundary | No LAN exposure, browser drive-by or ambiguous framing | IPv4 `127.0.0.1` binding, exact `Host`, rejected `Origin`, exact single Authorization and Content-Length, no Transfer-Encoding, HTTP/1.1 only, bounded line/body/header parsing |
| Resource and Decision APIs | Same-user local capability only | Separate Unix sockets, current-UID peer verification where available, mode `0600`, symlink/race-resistant socket creation and removal |
| Provider endpoint | No plaintext credential transport, DNS rebinding or redirect credential leak | HTTPS only, no embedded credentials, all resolved addresses validated, execution TCP pinned to one validated numeric address while TLS authenticates the original hostname, redirects disabled, response/body/time limits |
| Provider Center import | UI cannot substitute endpoint or source account | Provider family and site select a Controller-owned endpoint template; strict request keys and optimistic revision checks; explicit confirmation before Keychain copy |
| Routing and proxy configuration | No loose files, symlink replacement or partial writes | User-owned mode-`0700` parents, regular mode-`0600` documents, `O_NOFOLLOW` where available, bounded strict JSON, duplicate-key rejection, atomic replace and fsync |
| Install, rollback and uninstall | No mixed running image or unsafe path deletion | Exact executable matching, visible-helper stop/reopen, signed/hash-validated bundle swap, HOME-contained state, identity validation and fail-closed cleanup |

## STRIDE review

| Threat | Abuse case | Control and evidence | Residual decision |
| --- | --- | --- | --- |
| Spoofing | Another process calls the proxy without user authorization | Random Bearer capability; constant-time verifier comparison; missing, duplicate and rotated credentials return `401` | Any same-user process that obtains the Bearer can use it. This is an explicit local capability model, not per-process authorization. |
| Tampering | A local process replaces a socket/config or submits stale UI state | Private parent ownership/mode checks, socket identity quarantine, no-follow file reads, exact JSON schemas and revision conflicts | A process already executing as the same macOS user remains inside the local trust domain. |
| Repudiation | A route is executed and later cannot be explained | Content-free decision and attempt evidence records target, outcome and reason without model content or credential material | Evidence intentionally cannot reconstruct prompts or responses. |
| Information disclosure | API key, Bearer, prompt or Provider response enters logs/API/SQLite | Secret scans, strict response allowlists, sanitized exceptions, no HTTP request logging, content-free ledgers and one-time Bearer display | Process memory and the system clipboard while explicitly copied are not durable-secret stores; same-user debugging privileges are outside this boundary. |
| Denial of service | Slow, oversized or concurrent loopback requests exhaust the collector | 8-thread semaphore, five-second client timeout, 300-second absolute deadline, 8 KiB request line, 2 MiB body, 4 MiB upstream response and bounded retry count | A same-user process can still consume the deliberately exposed local capacity within those bounds. Routing failure must remain isolated from collection. |
| Elevation of privilege | UI imports an Admin/billing key as an inference key or redirects it to an attacker endpoint | Allowlisted inference families only; OpenAI Organization Admin, Generic quota and Daily Feed credentials excluded; imported endpoints are server-owned and site-locked | Manually created execution connections intentionally allow a user-chosen public HTTPS Provider and require a separately supplied credential. |

## Protocol abuse cases already covered

- Duplicate `Authorization`, `Content-Length` or JSON keys.
- `Transfer-Encoding`, chunked bodies, HTTP/1.0 and request smuggling forms.
- Missing or unexpected `Host`, browser `Origin`, absolute/ambiguous paths and
  unsupported methods.
- Oversized request line, body, provider response and slow clients.
- Concurrency exhaustion and server shutdown with active requests.
- Authentication failure, token rotation, hot enable/disable and same-port
  verifier replacement.
- 408, 429, selected 5xx and transport failure before the first downstream
  byte; no transparent target change after streaming begins.
- Client disconnect before and after route lock.
- Provider import with stale revisions, unexpected Provider kind, modified
  endpoint fields, missing source secret and configuration-write rollback.

## Security hardening resolved during pre-review

The pre-review originally found a DNS validation/connection TOCTOU in the
standard HTTPS path. Execution now resolves once, rejects the complete result
set if any address is unsafe, connects directly to a validated numeric address,
and still uses the original hostname for TLS SNI and certificate verification.
It may try another validated address only when connection/TLS setup fails
before request bytes are sent. Provider redirects remain disabled. Dedicated
tests simulate a resolver that would return loopback on a second lookup and
prove that no second lookup occurs.

## Residual risks requiring independent judgment

1. **Bearer is a same-user capability.** The proxy is not bound to a code-sign
   identity or per-client process. A local process that reads the explicitly
   copied Bearer can submit requests until rotation or disable.
2. **Content exists transiently in memory.** The product makes no promise
   against a debugger, crash dump or process with the same user's privileges.
   It promises only that content is not deliberately persisted or logged.
3. **Manual endpoints are a power-user feature.** A user can intentionally send
   a separately supplied routing credential to a public HTTPS endpoint they
   configured. Provider Center reuse does not permit this endpoint substitution.
4. **Ad-hoc local signing is not distribution trust.** The local drill proves
   bundle integrity and transactional recovery, not Apple Developer ID
   notarization or independent supply-chain provenance.

## Reproducible reviewer commands

Run from a clean candidate checkout without real credentials in fixtures or
logs:

```bash
scripts/audit_dependencies.sh
.build-venv/bin/python scripts/release_secret_scan.py
.build-venv/bin/python -m unittest discover -s tests -q
swift test --package-path swift_app --warnings-as-errors
scripts/release_smoke.sh
python3 scripts/measure_routing_performance.py --samples 500
```

For an installed candidate, additionally verify deep signing, Resource and
Decision socket mode/ownership, proxy default-off state, invalid/rotated Bearer
behavior, and one deliberate N-1 rollback. Never paste a real Bearer or
Provider credential into review evidence.

## Independent exit gate

The 0.8 security gate passes only when a reviewer outside the implementation
path:

- confirms no unresolved High or Critical finding;
- verifies the pinned-address transport and classifies the same-user capability
  model explicitly;
- reproduces dependency, secret, privacy, proxy abuse and rollback gates;
- records any accepted residual with an owner and review date; and
- signs off without changing the public Canary count or release metadata.

Until then, 0.8 remains a local candidate and Learned Router remains shadow-only.
